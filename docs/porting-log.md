# Porting log

Every capability brought into this app from FigCraft, DesignCraft or `craft-libs`: what was
taken, how (lifted as a crate, depended on, or re-implemented against the host model), and why.
The capability-by-capability plan is in [`recon.md`](recon.md) §9; decisions that need the owner
go to `docs/decisions/`.

## Phase 1: Foundations (2026-11-18)

Nothing was ported. Every Phase 1 item was either already in the host or built here.

| Item | Source considered | Decision | Why |
|---|---|---|---|
| Base | storytold/deckcraft `main` | Merged upstream `main` (v0.19.0, `5c69849`) into the fork | The owner chose to move first. 132 commits, no conflicts; the patches' tests and `cargo xtask ci` pass on the result. Brings the `craft-libs` cut-overs (DrawingML geometry and colour, the `.deckcraft` package layer, video codecs) that later phases build on |
| Enforced layering | DesignCraft `xtask/src/layers.rs` | Keep the host's | The host already has `cargo xtask layers` with the same shape (layer table, UI-crate ban below L6, dev-dependency exceptions) and it runs in `cargo xtask ci`. 18 crates, no violations |
| Command registry | FigCraft `cmd.rs` (`spec!`), DesignCraft `cmd.rs` | Keep the host's; add audit tests | The host and DesignCraft registries are the same design; FigCraft's lacks `enabled` and keeps menus apart. What was missing was a check, not a mechanism ([`command-audit.md`](command-audit.md)) |
| Copy-on-write document, O(1) undo | FigCraft `imbl` node map; DesignCraft `Arc` spreads | Keep the host's; measure it | The host already shares every untouched slide, master and media item between undo steps (`Arc<Slide>`, `Arc<Master>`, `Arc<Vec<u8>>`), with a byte budget. `imbl` is MPL-2.0, outside the licence allowlist. Measured: an undo step keeps ~28 KiB on a 100-slide deck against ~21 KiB on an 8-slide one, so the cost follows the slide edited, not the deck |
| Golden-image harness | DesignCraft's damage-region pixel tests; FigCraft's retained-render random walk | Built in the host | Both siblings compare renders inside their own renderer's tests against their own document model. The host needed whole-deck comparison against stored pictures: `deckcraft_render::golden` (compare with a channel and area tolerance, a diff picture, PNG decode) and `crates/engine/tests/it/golden.rs` |
| `.pptx` round trip by pixels | — | Built in the host | `crates/engine/tests/it/pptx_roundtrip.rs`: each sample deck goes through `.pptx` and must still match its golden pictures; `DECKCRAFT_PPTX_CORPUS=<folder>` runs a loss report over decks kept outside the repository |

## Phase 2: Typography (2026-11-23)

The owner gave the go-ahead on 2026-11-23 without choosing between the shared crates and copies
(recon §11 item 3); this phase uses the recommended default, the shared `craft-text`, which is
also upstream's rule for `craft-libs`.

| Item | Source considered | Decision | Why |
|---|---|---|---|
| Paragraph composer (Knuth–Plass) | DesignCraft `compose::breaker`; `craft-text::linebreak` | Depend on `craft-text` (`linebreak`, `hyphen`) at the rev the workspace already pins (`63196e6`); re-implement the item builder against the host's shaped cells (`crates/text/src/compose.rs`) | `compose` takes DesignCraft's `Document`/`Story` and cannot be lifted (recon §1 item 4). `craft-text` is the same breaker extracted with no document types: box/glue/penalty items, three elasticity tiers, rag, hyphenation zone, hanging edges, and a greedy fallback with bounded work. The host keeps its shaping, bidi and placement; only the choice of breaks changes |
| Hyphenation | DesignCraft `compose::hyphen`; `craft-text::hyphen` | `craft-text`, US English only | Bundled public-domain dictionary plus CC0 patterns. The other languages' hypher patterns carry licences outside the allowlist, so no language feature is enabled; non-English runs (by `lang`) are not hyphenated |
| Optical margin alignment | DesignCraft `compose::breaker::hang` | Copied the protrusion table; applied through `craft-text`'s `Item::hang` | Sibling Craft code (MIT OR Apache-2.0) may be copied (AGENTS.md §2). The table is standard protrusion amounts; the placement change is the host's |
| Where the switch lives | — | Three optional `ParaProps` fields (`composer`, `hyphenate`, `opticalMargin`) that inherit through masters, layouts and placeholders like every other paragraph property | Unset means the single-line breaker, so every existing deck and every `.pptx` lays out exactly as before (tested). New decks can opt in per style level |
| `.pptx` storage | — | An `a:pPr/a:extLst/a:ext` with SlideCraft's own URI and `sc:typography` | PowerPoint has no markup for these. Extensions with unknown URIs are kept and ignored, so SlideCraft round-trips them and PowerPoint breaks lines its own way. Saved text never changes: an automatic hyphen is drawn, not inserted |
| Paragraph and character styles | DesignCraft `doc::styles` (paragraph/character styles with based-on chains) | Re-implemented on the host model (`crates/model/src/text_style.rs`, `style.*` commands) | DesignCraft's styles hang off its own story model. Here a style is a named `ParaProps` + `RunProps` pair; paragraphs and runs name one, and `resolve::para`/`resolve::run` put it between direct formatting and the placeholder chain. Built-ins (Title, Subtitle, Heading, Body, Caption, Quote, Big Number; Strong, Emphasis, Accent) use theme fonts and colours, so they restyle with the theme; Phase 4's variables will take over that binding |
| Styles in `.pptx` | — | Flattened into direct formatting per shape on export; ids in `a:pPr`/`a:rPr` extensions; the deck's definitions as JSON in a `p:presentation` extension; the reader strips what the styles supply | PowerPoint has no named text styles. Flattening shows the same text in PowerPoint; stripping on import makes the round trip exact, so editing a style later still reaches the paragraphs |
| Readable coloured styles | — | Built here | A style's text colour with under 3:1 contrast against the shape's solid fill gives way to the shape's own text colour, in rendering and in the `.pptx` flattening alike. Found when Big Number (Accent 1) vanished on the default Accent 1 shape |
| Baseline grid | DesignCraft `compose::grid` (page grid, align-to-grid per paragraph) | Re-implemented (`BaselineGrid` on slide, layout and master; `ParaProps::snap_to_grid`; `snap_to_grid` in `crates/text/src/layout.rs`) | The idea is the same: lines of opted-in paragraphs move down onto the next grid line, later lines move with them. The grid is resolved once into `resolve::Ctx`, so every caller of `layout` (drawing, carets, hit testing) sees the same lines without a new option. Only horizontal text in unrotated, unflipped shapes snaps; shapes inside groups snap by their own coordinates. `.pptx` keeps it in a `p:extLst` extension that the reader takes back out of the kept extensions |
| Threaded text | DesignCraft `compose` threaded frames (a story laid out frame after frame) | Re-implemented (`Shape::thread_next`; `deckcraft_render::thread`; `text.threadTo`, `text.unthread`) | DesignCraft's stories live apart from frames; here the first box holds the text and `thread::flow` lays it out box after box, cutting at the first line a box cannot hold, so drawing, PDF and placed text all use the same flowed slide. Editing a later box edits the first. `.pptx` gets each box's part as real text (PowerPoint has no threads) plus a `cNvPr` extension naming the next box and whether a paragraph was cut; the reader joins it all back into the first box. The flow runs in the engine before export, because the layering keeps `pptx` from depending on `render` |
| Text wrap | DesignCraft `compose::wrap` (contour and bounding-box wrap with per-line exclusions) | Re-implemented, bounding box only (`Shape::text_wrap`; obstacles in `resolve::Ctx`; per-line cuts in `crates/text/src/layout.rs`; `arrange.textWrap`) | The obstacle carries the wrap, as in page layout. Each line keeps the wider side of every obstacle it meets, from line positions estimated at the paragraph's line pitch; both breakers take per-line widths, so the paragraph composer still balances the cut lines. Text not anchored at the top is stacked twice so the cuts follow where anchoring puts the lines (found on a screenshot of a middle-anchored box). Unrotated shapes, one column, horizontal text. `.pptx` keeps the margin in a `cNvPr` extension; PowerPoint lays the text out unwrapped |
| Pro tables | DesignCraft `compose::table` (column styles, decimal tabs) | Re-implemented on the host's tables (`Table::col_formats`, `Table::header_style`; `table.columnFormat`, `table.headerStyle`) | Banding, header/total rows and first/last columns were already the host's (PowerPoint has them). Added per-column alignment, alignment on the decimal point and paragraph styles, and a header-row style, applied in `deckcraft_render::table::cell_body`, the one path drawing, carets and typing share. Decimal alignment right-aligns each paragraph and pads it by how much narrower its shaped fraction is than the column's widest (counting digits failed: Inter's figures are proportional). `.pptx`: alignment and styles are written onto the cells, marked as coming from the column, and the formats ride in an `a:tblPr` extension; the reader takes the derived settings back out. Decimal padding is not written (PowerPoint gets right alignment) |

## Phase 3: Canvas and layout (2026-11-23)

`storytold/craft-libs` was checked first (AGENTS.md "Shared libraries"): it has no layout,
path-boolean or vector-network crate. FigCraft (`storytold/figcraft` `main`) is the behavioural
reference; its `figcraft-layout` and `figcraft-pathops` work on `figcraft_doc::Document`, whose
node store is `imbl` (MPL-2.0, outside the allowlist), so nothing was lifted from them.

| Item | Source considered | Decision | Why |
|---|---|---|---|
| Grid view and single-slide view | FigCraft's canvas board; the host's Slide Sorter | Keep the host's sorter as Grid view; add `view.grid` (Cmd/Ctrl+Alt+B) to switch in one keystroke | The sorter already has sections (add, rename, fold, drag), drag to reorder, multi-select and zoom. The view is window state ([`decisions/003-view-mode.md`](decisions/003-view-mode.md)) |
| Editing inside groups | FigCraft's selection (enter a frame or group, Esc out) | Re-implemented (`edit.selectChildren`, `edit.selectParent`; Enter, Shift+Enter, Esc; a double-click into a group; clicks pick members once inside) | The host kept members in each group's child space, so a member's stored box was not where it was drawn once the group moved; selection handles and drags would be off. `deckcraft_model::canvas::normalize_groups` now keeps every unrotated, unflipped group's child space equal to its box (on open and after each edit, for the slides the edit touched), which draws identically. Rotated and flipped groups are not entered |
| Distance measurement | FigCraft's Alt-hover measurement | Re-implemented (`arrange.measure` query; Alt over the canvas draws the distances) | Pure geometry (`cmd::canvas::measure`): gaps between boxes apart, edge to edge for boxes inside one another or overlapping |
| Frames | FigCraft `NodeKind::Frame` | Re-implemented as optional fields on a group (`Shape::frame`: clip, corner radius; the group's own `fill`, `line`, `effects`), as decision 002 says | A frame draws its box behind its members, may clip them, is not refitted to them, and stops fill/outline commands from recolouring its members. `frame.create`, `frame.set` |
| Constraints | FigCraft `apply_constraints` | Re-implemented (`Shape::constraints`; `canvas::constrain`; `layout.constraints`) | Applied in the same normalisation pass: when a frame's box differs from its child space it was moved or resized, so its members are placed by their pins (start, end, both, centre, scale) instead of being scaled |
| Auto layout | FigCraft `figcraft-layout` (flow, wrap, grid tracks, hug/fill/fixed) | Re-implemented as a pure solver (`deckcraft_model::autolayout::solve`) applied by the engine's canvas pass, innermost frame first; behaviour and tests modelled on FigCraft's | The FigCraft solver mutates its own document. Here the solver takes sizes and returns boxes, so it is tested without a document; the engine writes the boxes into the tree after every edit of a slide that has frames. `layout.set`, `layout.child`, `layout.remove`. Text is measured by the host's own autofit, not by the solver |
| Vector networks | FigCraft `VectorNetwork` (vertices, segments with tangents, regions) | Re-implemented (`deckcraft_model::vector`; `vector.create`, `vector.set`, `vector.moveVertex`, `vector.fromPath`, `vector.get`) | The network is stored on the shape in its own box and its geometry is derived from it: one fill-only custom path per region and one stroke-only path for the segments, runs through two-way points drawn as one path so corners join. The renderer, hit testing and `.pptx` (`custGeom` paths can be fill-only or stroke-only) need nothing new. A network whose outline is changed another way (Edit Points, Change Shape) becomes a plain path |
| Pen and pencil | FigCraft pen and pencil tools | Kept the host's: Curve and Freeform (pen), Scribble (pencil); `vector.fromPath` turns what they draw, or any preset, into a network (points that meet are merged) | The host's tools already draw Bézier and freehand paths with Edit Points; what was missing was the network, not the tool |
| Editable booleans | FigCraft `BooleanOp` nodes; `figcraft-pathops` (`linesweeper`) | Re-implemented on the host's Merge Shapes polygon overlay (`i_overlay`, already a dependency): a group with `Shape::boolean` (union, subtract, intersect, exclude) whose `geom` is the result, recomputed by the canvas pass after every edit; drawn with the group's own fill, outline and effects (`boolean.create`, `boolean.setOp`, `boolean.flatten`) | `figcraft-pathops` depends on `figcraft-doc`; `linesweeper` would be a second boolean engine next to `i_overlay`. Operands stay members, edited in place (P3.2) |
| Effects | FigCraft layer blur, background blur, noise (`figcraft-render`, tiny-skia) | Re-implemented on `vello_cpu` (`Effects::layer_blur`, `background_blur`, `noise`; `format.blur`, `format.noise`) | Layer blur is a blur filter layer around the shape. Background blur draws the slide's backdrop and the shapes below again, blurred, inside the shape's outline, before the shape (top-level shapes). Noise is a fixed grain tile (deterministic, so goldens are stable) over the fill |
| Display P3 colour | FigCraft `figcraft-color` (P3 colour spaces) | Depend on `craft-color-transform` and `craft-color` from `craft-libs` (rev `249a41b`) for the P3 → sRGB matrix and transfer curve; `Shape::p3` keeps the originals (`format.p3`) | The shared crate already has Display P3 primaries and Bradford adaptation. The renderer and window are sRGB, so the fill or outline holds the nearest sRGB colour (clipped per channel) and is what is drawn and saved to `.pptx`; the P3 original survives SlideCraft's own files and is dropped if the colour is changed another way |
| Phase 3 in `.pptx` | — | One shape-level extension, `sc:canvas` on `p:cNvPr` (JSON of the canvas fields; `crates/pptx/src/canvas_ext.rs`), plus two writer steps for PowerPoint: a frame's background rectangle as its first member (dropped on reading) and an editable boolean written as one `p:sp` with its result `custGeom` (rebuilt from its operands on reading) | PowerPoint keeps unknown extensions and ignores them, so it shows the nearest static result: resolved boxes, the frame's box, the boolean's result, the network's outline, the sRGB colour. One JSON extension rather than one element per feature keeps the 2026-12-14 slot migration to a single `Shape.raw_ext` line (`docs/upstream/craft-libs-fork-plan.md` §3) |
